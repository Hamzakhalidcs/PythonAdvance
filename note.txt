Logging have five levels you would use 
1: Debuge
2: info
3: Warning 
4: Error 
5: Critical 


Here's a rule I personally use

When choosing a log level, I ask:

Did everything work normally?
✅ INFO

Did something unexpected happen, but the program handled it?
⚠️ WARNING

Did an operation actually fail because of an error?
❌ ERROR

Can the application no longer continue?
🚨 CRITICAL



Here's a mental shortcut
I use this all the time.

DEBUG
"What is my code doing?"

INFO
"Everything worked."

WARNING
"Something unexpected happened, but it's okay."

ERROR
"One operation failed."

CRITICAL
"The application cannot continue."


Logging is the practice of recording events, message and data during a program execution. it's like
keeping a diary of what your program does ,when it does and any problems it encounters. 

A common principal is :
Log meaningful events, not every line of code. 

Threshold rule in logging always remember : 
            "The configured logging level is the minimum severity that will be displayed."
